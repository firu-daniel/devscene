# schemas/

`devscene.config.schema.json` is the JSON Schema (draft-07) for `devscene.config.json` — the repo-scoped configuration that names the adopting project's layers, verification commands, protected branches, run-artifact directory and optional phases. That file lives at the **root of the adopter's repository and is committed**, so every contributor and every headless run reads the same values, and a change to it is reviewable like any other change. The boundary is deliberate in both directions: machine-local values — filesystem paths outside the repo, background-daemon preferences, a secret's *value* — belong in the plugin's `userConfig`, which stores them per user and can mark a value sensitive, while any **constrained vocabulary** must live here instead, because the `userConfig` option schema has no `enum` and so cannot restrict a value to a fixed set. A third home sits outside both: what a remote run needs beyond `execution.target` — its runner, credentials and tunables — lives in the GitHub repository's own variables and secrets, as `docs/config.md` §2 states. A worked configuration is at `examples/devscene.config.json` at the harness root; the sibling `negative/` directory, beside this file, holds the fixtures that must be **rejected**, so a constraint whose whole purpose is to refuse an input has a file proving it does.

A flow graph's shape is not a schema of this directory. Its schema is `graphscene/src/graphscene/schemas/flow-graph.schema.json`, format 4, which ships with the GraphScene library; it validates the planning graph `cli/templates/scripts/flows/task_plan_writing.graph.json`, which `init` copies into the adopter's scripts directory, and GraphScene's own fixtures. It is checked from the repository root with:

```
npm run validate:graphscene-schema
```
