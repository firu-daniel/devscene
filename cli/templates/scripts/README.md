# scripts/

The project-command wrapper scripts `init` writes into the configured `scriptsDir`: type-check, test and dev-server, configured through `commands.*` in `devscene.config.json`, and deploy, configured through `deploy.command` on the separate `deploy` object — so no build tool and no hosting provider is hardcoded anywhere in the harness. They exist as scripts rather than as raw command lines because an unattended run's permission profile can allow-list a literal script path far more safely than an arbitrary command, which is why `commands.<key>` holds the **wrapper invocation** `bash <scriptsDir>/<name>.sh` — the literal the profile allow-lists — while the **raw** command line lives inside the script. Which raw line that is follows one precedence, and it is what keeps the pair from being circular: a raw command line already sitting in `commands.<key>` wins, because an adopter who edited it there meant it — and that state is **reported** rather than silently blessed, since the raw line is not the value the permission profile allow-lists: `init` names it as it writes the wrapper from it, `config set` names it as the value is stored, and `doctor`'s `command-wrappers` check grades it on every later run; otherwise, when that key holds this wrapper's own invocation — the normal state after a first `init` — the body is the line stack detection produced; and when neither resolves, the body names what to fix — the key to set, or for `deploy`, which detection never supplies, this script itself — and exits non-zero rather than appearing to have run a check it never ran. Two states get no wrapper at all, and therefore no allow entry: a key still holding the placeholder `init` writes for a command it could not detect, and `commands.typecheck` holding the `<none>` sentinel — the first is unfinished and is the one that asks the adopter to do something about it, the second is the answer that this repository has no such command and asks for nothing. **Each script prints its own verdict line**, so a caller never appends an exit-code probe to it: that compound form is what an unattended run's permission mode refuses — except `start-dev-server.sh`, which has no verdict to give because it starts a long-running process. Every wrapper anchors itself to its own checkout before it runs and forwards whatever arguments it was given to the **last** command of its raw line — whether that command accepts a bare path or name filter is a property of the command, not of the wrapper, so a line ending in a sub-command's own flags takes none; `docs/cli.md` §5 is the full contract.

**The other family in this directory is not generated.** The run watcher, its restart wrapper, the notifier and its stream formatter, the commit / push / branch-refresh / worktree / cleanup wrappers, the scratch runner, the flow walker `flow-walker.sh`, which hands each call to `devscene-flow-walker` in `<scriptsDir>/python/.venv`, its graph `flows/task_plan_writing.graph.json`, whose second reader is the planning driver, the Run gates wrapper `run-test-suite.sh`, the gate launcher `launch-sandboxed-gates.sh`, the run-analytics script (`run-analytics.sh`, with `lib/run-analytics.jq` and `lib/run-analytics-report.jq`), which the watcher runs after every headless session to record that session's time, cost and reliability, the network calls the sandbox refused, and possible network attempts in finished gate logs under `<state_dir>/run_analytics/` and, where a Run gates round wrote its own timing records, that round's gate and test-file seconds, the docs-retrieval server launcher, `lib/unit-commit-lib.sh`, the library `commit-on-branch.sh` sources for its unit and artifact front end, `remote-run.sh` (sends a remote run's dispatch, pause, warm-up and stop to GitHub; run by the watcher, the remote job and a person), the prompt-injection screen `prompt-injection-screen.sh`, the provisioning script `flow-host-provision.sh`, `task-offer-check.sh`, the review sweep `review-sweep.sh`, which `branch-reviewer` runs from the main checkout to apply the default branch's `.claude/review-sweep.md` rows to a branch's added lines, and the shared library at `lib/harness-run-lib.sh` are copied byte for byte into the same `scriptsDir`, because each reads `devscene.config.json` *at run time* rather than carrying a value frozen in when `init` ran — a guard whose protected-branch set was baked into a file at generation time enforces the wrong set the moment that list changes, and does it silently. They therefore carry no `{{token}}` at all. `flows/task_plan_writing.graph.json` is the graph `flow-walker.sh` passes `devscene-flow-walker` to walk. `cli/src/generators/outerLoopScripts.ts` declares that set and marks which of its rows an agent may invoke; `cli/scripts/README.md` records why they live under `scriptsDir` rather than in the installed package. **One of them runs a file it is given:** `scratch-run.sh` runs an agent's language probe or mutation check in the interpreter that file's extension names, and refuses any argument that does not resolve inside `<state_dir>/scratch/`. **Three of them are run by the orchestrating session:** `flow-walker.sh` prints the next routing step of the planning flow and keeps machine-local state in the directory `<state_dir>/.flow_walker_state/`, one file per branch; `run-test-suite.sh` is run once per Run gates round and has two forms: the run form starts the whole-tree type check `commands.typecheck` and then the test command `commands.test` detached from the calling session, writing their output to a per-round log under `<state_dir>/test_run_logs/`, and prints `pending` — or prints its label's finished verdict at once when that run finished on the commit the checkout is at, with nothing changed since; `--wait <label>`, re-issued after each `pending`, prints `pass` or `fail <log path>` once that round has finished; `prompt-injection-screen.sh` screens the input files a person added to a run before an unattended engine reads them — its verbs print each file's SHA-256 and pre-scan hits, which files the agent must still screen, the question file it parked an unsafe one in, and the parsed `verdict: SAFE` or `verdict: UNSAFE` — and the session runs the main checkout's copy, sandboxed, never a run copy's; it is a tripwire, not a boundary. On the opt-in script-driven planning path the watcher launches the planning driver `devscene-planning-driver` from `<scriptsDir>/python/` through `hr_flow_host_exec` in `lib/harness-run-lib.sh`; the driver walks the graph in-process and runs no `flow-walker.sh`. **One of them is started by neither the watcher nor an agent:** `docs-search-server.sh` is started by the agent runner from `.mcp.json` when `docs.retrieval` is on, and starts the backend `docs.retrievalBackend` selects: it `exec`s the machine-shared retrieval runtime's `docs serve` by default, or runs the Python package's `devscene-docs-retrieval serve-mcp` when the key is `python` (its header carries the full exit contract). **One of them is run by an interactive session:** the change-request fence in `.claude/CLAUDE.md` runs `task-offer-check.sh` bare from the checkout root to learn whether the offer may proceed; it prints the main checkout and exits 0 only then, and the generated `.claude/settings.json` allow-lists exactly that invocation. **One of them is never run by an agent, and only outside the sandbox:** `flow-host-provision.sh` takes no argument and builds the flow walker's environment with `uv sync --frozen --no-dev --no-editable`; `init` runs it by default after wiring, without asking, unless `--no-provision-python` is given, a person runs it, `doctor` names it as its remedy, and `setup-worktree.sh`'s step 6 runs the same sync for a run copy through `lib/harness-run-lib.sh` rather than through the script, and fails the bootstrap when `uv` is not on PATH or the flow host's project is missing. `<scriptsDir>/python/` carries the two packages it syncs from, `graphscene/` and `devscene-flow-host/`, and the environment `.venv` it builds. A person runs it from the checkout root:

```
bash <scriptsDir>/flow-host-provision.sh
```

This family is written `create-if-absent`, so a plain re-run of `init` keeps the copy a repository already has. A repository already wired picks up a changed script with the command below, which replaces each script of this family whose bytes differ from the shipped one, an edited copy included, after a backup, while the wrapper family above stays as written:

```
npx devscene init --upgrade
```
