# The `devscene-flow-host` layer

> **Read this when:** the change you are implementing or reviewing lands under `devscene-flow-host/` — the package `devscene_flow_host` (its `commands`, `host` and `records` layers), its `pytest` suite, its `pyproject.toml` or its `uv.lock`. **Skip when:** it lands in another layer; GraphScene itself is `.claude/context/graphscene.md`, and the rules that span every layer — the Python stack, the testing bar and the commit-message policy among them — are `.claude/context/conventions.md`, which this document assumes has been read.

**Purpose.** The rules this layer's implementer and its reviewer both read before they start.

## What this layer is, and what it is not

- **It is the harness's GraphScene host, imported as `devscene_flow_host`.** What belongs in it, what goes to its own `devscene`-prefixed package and what goes to `graphscene/` instead is owned by `.claude/context/conventions.md` → `## The layers` and `### Where a new responsibility goes` (`devscene-flow-host/README.md` → `## What it is`; `devscene-flow-host/src/devscene_flow_host/__init__.py` module docstring). This layer's consequence: a change that is useful without DevScene, or a DevScene Python integration that does not feed GraphScene, has drifted out of this layer.
- **It stays in this repository, and adopters never import it**; that rule is `.claude/context/conventions.md` → `## The layers`, and the route by which it reaches an adopter, shipped in the npm package and copied under `<scriptsDir>/python/`, is that document's `devscene-flow-host/` bullet, and every caller launches it through `flow-walker.sh`'s hand-off, as that bullet states (`devscene-flow-host/README.md` → `## What it is`, `## The command line`).
- **Source lives under `devscene-flow-host/src/devscene_flow_host/`, tests under `devscene-flow-host/tests/`.** The wheel packages `src/devscene_flow_host` and nothing else (`devscene-flow-host/pyproject.toml` → `[tool.hatch.build.targets.wheel]`). File naming follows the always-loaded file's **Python source module** and **Python test suite** rows.
- **The package is typed**: `devscene-flow-host/src/devscene_flow_host/py.typed` ships with it inside the wheel's `src/devscene_flow_host`, as `graphscene/src/graphscene/py.typed` does for the sibling package (`devscene-flow-host/pyproject.toml` → `[tool.hatch.build.targets.wheel]`; `.claude/context/graphscene.md` → *"The package is typed"*).

## The internal layers

| Layer | Path | Holds | May import |
|---|---|---|---|
| `commands` | `devscene-flow-host/src/devscene_flow_host/commands/` | The command lines over the host: locating and loading the graph file, rendering a `Step` or a refusal, and the exit status | `host`, `records`, `graphscene`'s public surface, the standard library |
| `host` | `devscene-flow-host/src/devscene_flow_host/host/` | GraphScene's protocols over the records — the `PredicateHost`, the walk's `StateStore`, the composed `Walker` — and the harness's rules over its records | `records`, `graphscene`'s public surface, the standard library |
| `records` | `devscene-flow-host/src/devscene_flow_host/records/` | The repository's records read into plain values; it answers no GraphScene protocol | `records`, the standard library |

(`devscene-flow-host/README.md` → `## The layers`; each layer's `__init__.py` docstring → *"The rule:"*; `devscene-flow-host/src/devscene_flow_host/host/predicates.py` and `devscene-flow-host/src/devscene_flow_host/host/walking.py` → *"Deliberately not covered"*.)

- **Imports point down only — `commands` over `host` over `records` — and `records` never imports `graphscene`.** The contracts `devscene-flow-host-layers` and `devscene-flow-host-graphscene-outside-records` hold this (`devscene-flow-host/pyproject.toml` → `[tool.importlinter]`), run with no cache by `devscene-flow-host/tests/test_layers.py`.
- **A new module lands in the layer its work belongs to** (`devscene-flow-host/README.md` → `## The layers`). Reading a record into a value is `records`; answering a GraphScene protocol over it is `host`; rendering and exit statuses are `commands`.
- **The package root exports nothing (`__all__: list[str] = []`), and no module inside the package imports from the package root: each imports the defining module of what it needs** (`devscene-flow-host/src/devscene_flow_host/__init__.py` → `__all__` and *"each imports the defining module of what it needs"*; `devscene-flow-host/src/devscene_flow_host/host/predicates.py` → `from devscene_flow_host.records.config import`). Tests import the same way (`devscene-flow-host/tests/test_config.py` → `from devscene_flow_host.records.config import`).

## What it may depend on

- **A module under `devscene-flow-host/src/devscene_flow_host/` imports only the standard library, `devscene_flow_host` itself and the distributions `[project] dependencies` declares.** Static `import`, absolute `from … import` and a constant-name `importlib.import_module` / `import_module` / `__import__` call are all checked (`devscene-flow-host/tests/test_boundary.py` → `scan`, `allowed_names`; `devscene-flow-host/README.md` → `## What it may depend on`).
- **An import neither gate sees still binds**: a module name computed at run time, or one passed to `importlib.import_module` past what `scan` recognises, is checked by the reviewer reading it (`devscene-flow-host/tests/test_layers.py` → *"A reviewer checks those by reading"*; `devscene-flow-host/tests/test_boundary.py` → *"Deliberately not covered"*).
- **This layer's consequence of the GraphScene boundary**, which `.claude/context/conventions.md` → `## The layers` owns: a name this package needs from GraphScene is reached through `graphscene`'s public surface, so where it is missing the change is to `graphscene.__all__`, made in the `graphscene` layer, never a submodule import here (`devscene-flow-host/tests/test_boundary.py` → `_names_from_root`, `test_rule_b_flags_a_graphscene_submodule`).
- **`graphscene` stays an editable path source on `../graphscene`** (`devscene-flow-host/pyproject.toml` → `[tool.uv.sources]`; pinned by `devscene-flow-host/tests/test_graphscene_dependency.py` → `test_the_manifest_sources_graphscene_from_the_editable_sibling`), so this package imports the checkout's own `graphscene/src/graphscene/` (`test_graphscene_imports_from_this_checkouts_sibling`). When the lock must move is owned by `.claude/context/conventions.md` → `## The layers` and `## What accompanies a new unit of each kind`.
- **`devscene-flow-host/uv.lock` moves only through a re-lock** — `bash scripts/python-service.sh --package devscene-flow-host lock` — never by hand edit (`devscene-flow-host/tests/test_graphscene_dependency.py` → `_RELOCK` and the module docstring's *"only a re-lock moves them"*; `devscene-flow-host/README.md` → `## The lock follows GraphScene`).
- **A declared dependency whose import name differs from its normalised PEP 508 name gets an entry in `_IMPORT_NAMES`, keyed by that normalised name, when it is added** (`devscene-flow-host/tests/test_boundary.py` → the comment above `_IMPORT_NAMES`). Without it the boundary test flags every import of that dependency.
- **A module under `devscene-flow-host/tests/` stays inside the same boundary, widened only by the `dev` dependency group**: the standard library, `devscene_flow_host`, the declared runtime dependencies through their public surface, the `dev` group's tools and the suite's own support modules — never another package's tests or another layer's source. Reading another layer's tracked file as test input is not an import (`devscene-flow-host/README.md` → `## What it may depend on`). `devscene-flow-host/tests/test_boundary.py` does not scan `tests/` (*"Deliberately not covered"*), so a reviewer checks this by reading.
- **Tooling goes in the `dev` dependency group, never in `[project] dependencies`** (`devscene-flow-host/pyproject.toml` → `[dependency-groups]`, which carries `import-linter`): every runtime dependency widens the boundary test's allowed set (`devscene-flow-host/tests/test_boundary.py` → `allowed_names`).

## Records, and which one is the truth

- **A record reader reads its record as the harness's bash reader of it does — for the run mode, as the retired bash walker's did — and its docstring rule names that bash function** (`devscene-flow-host/src/devscene_flow_host/records/config.py` → `hr_config_load`, `hr_state_dir`, `hr_phase_enabled`; `devscene-flow-host/src/devscene_flow_host/records/ledger.py` → `fw_run_mode_skipped`, `fw_id_in_list`; `devscene-flow-host/README.md` → `## What it reads, answers and keeps`). A cited `fw_*` name or `flow-walker-gates.sh` path names the retired walker's code, read in its history before #419 (`devscene-flow-host/README.md` → `## Differences from flow-walker.sh` → *"name the retired walker's functions"*). A reader returns values and decides nothing about what they mean to the walk (`devscene-flow-host/src/devscene_flow_host/records/config.py` → *"decides nothing about what they mean to the walk"*; `devscene-flow-host/src/devscene_flow_host/records/ledger.py` → *"decides nothing with it"*).
- **A record read is a frozen dataclass whose attributes are the snake_case form of the keys read**, its mappings read-only (`devscene-flow-host/src/devscene_flow_host/records/config.py` → `HarnessConfig`, `state_dir` from `stateDir`, `MappingProxyType`; `devscene-flow-host/src/devscene_flow_host/records/ledger.py` → `RunMode`, `RunModeUnresolved`; asserted by `devscene-flow-host/tests/test_config.py` → `test_the_config_is_frozen_and_its_phases_cannot_be_assigned`).
- **The records are the source of truth, re-read on every arrival**: `HarnessPredicateHost` reads `devscene.config.json` and the flow-progress ledger on every call, so a ledger written mid-walk is seen at the next arrival; `open_walker` reads the configuration once, for `stateDir` only (`devscene-flow-host/src/devscene_flow_host/host/predicates.py` → *"The records are re-read on every call"*; `devscene-flow-host/src/devscene_flow_host/host/walking.py` → *"The configuration is read once, for `stateDir`"*; `devscene-flow-host/tests/test_predicates.py` → `test_the_records_are_re_read_on_every_call`).
- **The ledger's `## Run mode` → `- skipped:` line wins whenever the ledger exists; the caller's skipped ids are used only when no ledger exists; with neither, the result is `RunModeUnresolved` carrying the reason, never a guess** (`devscene-flow-host/src/devscene_flow_host/records/ledger.py` → `read_run_mode`; `devscene-flow-host/tests/test_ledger.py` → `test_the_ledger_wins_over_the_given_ids`).
- **A predicate the host cannot answer is `None`, which the walk refuses, and `refusal_reason` gives the reason**; only the `phase_<p>_off` and `run_mode_skips_<id>` name patterns are answered (`devscene-flow-host/src/devscene_flow_host/host/predicates.py` → `PHASE_PREDICATE`, `RUN_MODE_PREDICATE`, `_resolve`).
- **Each branch's walk is its own GraphScene `FileStateStore`, at `<stateDir>/.flow_walker_state/<quote(branch, safe="")>.json`**, and everything the store writes stays inside that directory; another branch's walk is never read (`devscene-flow-host/src/devscene_flow_host/host/store.py` → `walk_state_path`, `walk_store`; `devscene-flow-host/tests/test_store.py` → `test_everything_written_stays_inside_the_state_directory`). The state file's format is GraphScene's codec, owned by `.claude/context/graphscene.md`.
- **A record the host keeps beside the walk is its own per-branch JSON file in a named subdirectory of `<stateDir>/.flow_walker_state/`, its directory name a `Final` constant, written whole and only while `RefusalStore`'s lock is held** (`devscene-flow-host/src/devscene_flow_host/host/refusals.py` → `REFUSALS_DIRECTORY`, `refusals_path`; `devscene-flow-host/src/devscene_flow_host/host/revision_findings.py` → `REVISION_FINDINGS_DIRECTORY`, `revision_findings_path` and *"Every write and clear happens while the caller holds `RefusalStore`'s lock"*). `start_walk` and `record_outcome` take `RefusalStore`'s lock, then the walk store's; `current_step` takes neither (`devscene-flow-host/README.md` → `## Differences from flow-walker.sh` → **The locks.**).

## Shared code and constants

- **A record's fixed file name, directory name and fixed in-record literals are module-level `Final` constants in the module that reads or writes them, and another module imports them from there** (`devscene-flow-host/src/devscene_flow_host/records/config.py` → `CONFIG_FILENAME`, `DEFAULT_STATE_DIR`, `PHASES`; `devscene-flow-host/src/devscene_flow_host/records/ledger.py` → `LEDGER_DIRECTORY`, `_RUN_MODE_HEADING`, `_SKIPPED_PREFIX`; `devscene-flow-host/src/devscene_flow_host/host/store.py` → `STATE_DIRECTORY`). A per-branch file name is composed in its path function, its suffix written inline there (`devscene-flow-host/src/devscene_flow_host/records/ledger.py` → `ledger_path`, `_progress.md`; `devscene-flow-host/src/devscene_flow_host/host/store.py` → `walk_state_path`, `.json`); whether those suffixes must also become constants is `## Not determined` below. The phase list is `PHASES`, and `PHASE_PREDICATE` is built from it rather than from a second list (`devscene-flow-host/src/devscene_flow_host/host/predicates.py` → `PHASE_PREDICATE`).
- **The suite turns a PEP 508 requirement string into a dependency name in one place, `devscene-flow-host/tests/requirement_names.py` (`dependency_name`)**: lower-cased, `-` as `_`. A test needing that normalisation imports it rather than writing another (`devscene-flow-host/tests/requirement_names.py` → *"The rule this module exists to enforce"*; imported by `devscene-flow-host/tests/test_boundary.py` and `devscene-flow-host/tests/test_graphscene_dependency.py`).
- **A module states the rule it holds in its docstring, under *"The rule:"*, and lists what it deliberately leaves out under *"Deliberately not covered"* (or *"Deliberately not checked"*)** (`devscene-flow-host/src/devscene_flow_host/__init__.py` → *"The rule: this package imports only"*; `devscene-flow-host/src/devscene_flow_host/records/errors.py` → *"The rule:"*; `devscene-flow-host/src/devscene_flow_host/host/store.py` → *"Deliberately not covered"*; `devscene-flow-host/src/devscene_flow_host/records/config.py` → *"Deliberately not checked"*).
- The stack's names and settings — `ruff`, `mypy` `strict` over `src` and `tests`, `pytest` options, every command through `scripts/python-service.sh` — are owned by `.claude/context/conventions.md` → `## The stack, in the words the rules below use`; this package's own copy is `devscene-flow-host/pyproject.toml` → `[tool.ruff]`, `[tool.mypy]`, `[tool.pytest.ini_options]`.

## Errors

- **`RecordError` is the one anticipated failure of reading a repository record** — absent, or not readable as the harness writes it — **with a one-line message naming the file and the cause** (`devscene-flow-host/src/devscene_flow_host/records/errors.py` → *"The rule:"*; exact messages asserted in `devscene-flow-host/tests/test_config.py` and `devscene-flow-host/tests/test_ledger.py`).
- **A missing file is the only `OSError` turned into a `RecordError`; any other `OSError` propagates unchanged**, and a `RecordError` propagates through `host` (`devscene-flow-host/src/devscene_flow_host/records/errors.py`; `devscene-flow-host/src/devscene_flow_host/records/config.py` → `read_config`, `except FileNotFoundError`; `devscene-flow-host/src/devscene_flow_host/host/predicates.py` → *"A `RecordError` propagates."*).
- **Which exit status either becomes is the `commands` layer's, never a reader's or the host's** (`devscene-flow-host/src/devscene_flow_host/records/errors.py` → *"Which exit status a `RecordError` becomes is the caller's"*; `devscene-flow-host/README.md` → `## Errors`). The cross-layer shape is `.claude/context/conventions.md` → `## Output, logging and errors`.
- **`devscene-flow-walker` answers by `flow-walker.sh`'s `EXIT CODES`: `0` an action printed; `1` a refusal — a usage error, a `Refused` step, `next` or `current` with no saved walk, no graph file; `2` a fault — a `RecordError`, a `GraphError`, a `TimeoutError`, any other `OSError` or `ValueError`, and every unanticipated exception as `internal error: <type>: <message>`; `3` `check-round-file`'s invalid file.** Every non-zero exit writes exactly one `flow-walker: <cause>` line on stderr and nothing on stdout, and only `KeyboardInterrupt` and `SystemExit` escape `main`; Python's own exit `1` and traceback never reach a caller, which reads exit `1` as a refusal (`devscene-flow-host/src/devscene_flow_host/commands/flow_walker.py` → the module docstring's *"The rule:"*, `main`, `failure`; `devscene-flow-host/README.md` → `## The command line`).
- **A rendered line keeps `flow-walker.sh`'s wire grammar — its keys, their order and its actions — wherever a caller parses it; a cause no caller parses may be worded by the host or GraphScene.** Every way the command answers differently from bash is an entry in `devscene-flow-host/README.md` → `## Differences from flow-walker.sh`, under **Chosen** or **Still open**, naming the suite it moves (`devscene-flow-host/src/devscene_flow_host/commands/render.py` → *"The rule:"*). The command reaches the walk only through `start_walk`, `record_outcome` and `current_step`, never `Walker`'s own methods (`devscene-flow-host/src/devscene_flow_host/commands/flow_walker.py` → *"The walk is reached only through the host's entry points"*).

## Tests — what "done" means here

- **Runner:** `pytest` over `devscene-flow-host/tests/`, as plain module-level `test_*` functions with type-annotated signatures, since `mypy` `strict` covers `tests` (`devscene-flow-host/tests/test_boundary.py`; `devscene-flow-host/pyproject.toml` → `[tool.mypy]`). The header rule and the no-fixture-in-checkout rule are owned by `.claude/context/conventions.md` → `## The testing bar`.
- **This suite's substitutes for a mock, observed: records planted under `tmp_path` and the code under test taking the root as a parameter; a planted package linted in a subprocess with `PYTHONPATH` pointed at it** (`devscene-flow-host/tests/test_predicates.py` → `_plant_config`, `_plant_ledger`; `devscene-flow-host/tests/test_layers.py` → `_plant`, `_lint`). Whether a mocking aid is admitted is `## Not determined` below.
- **Every expected value is a literal written from the rules, never taken from the output of the code under test** — this layer's consequence of `.claude/context/conventions.md` → `## The testing bar` (`devscene-flow-host/tests/test_config.py`, `devscene-flow-host/tests/test_ledger.py`, `devscene-flow-host/tests/test_walking.py` → *"never taken from"*).
- **A scanner or contract is tested against planted input under `tmp_path`, one case per clause it enforces asserting the exact violation text, plus one clean case, plus one case against the real package** (`devscene-flow-host/tests/test_boundary.py` → `_plant`, `test_a_clean_module_produces_no_violation`, `test_the_real_package_stays_inside_its_boundary`; `devscene-flow-host/tests/test_layers.py` → `_CLEAN_PLANT`, `_VIOLATIONS`, `test_the_real_package_keeps_every_layer_contract`).
- **A test whose failure has a fixed remedy names the command in its assertion message** (`devscene-flow-host/tests/test_graphscene_dependency.py` → `_RELOCK`).
- **One test file on its own**, run from the repository root as one plain command, with the path relative to `devscene-flow-host/`:

  ```
  bash scripts/python-service.sh --package devscene-flow-host test tests/<file>.py
  ```

  (`devscene-flow-host/README.md` → `## Running the toolchain`). A change reaching `devscene-flow-host/src/devscene_flow_host/**` or `devscene-flow-host/pyproject.toml` also runs the tree guards `tests/test_boundary.py` and `tests/test_layers.py` this way (`devscene.config.json` → `treeGuards`).
- **Lint and typecheck** are `bash scripts/python-service.sh --package devscene-flow-host lint` and `… typecheck`; the package is graded by gate 13's legs 13h–13j (`devscene-flow-host/README.md` → `## Running the toolchain`, `## Gating`; `docs/development.md` → **Gate 13**).

## What accompanies a new unit here

| New unit | What must land with it |
|---|---|
| A module under `devscene-flow-host/src/devscene_flow_host/` | A place in the layer its work belongs to; a docstring stating its rule and what it deliberately leaves out; nothing to register for the boundary test, which scans every `.py` file under the package (`devscene-flow-host/tests/test_boundary.py` → `scan`, `rglob`). |
| A new layer, or a changed import rule | Its contract change in `devscene-flow-host/pyproject.toml` → `[tool.importlinter]`, its planted cases in `devscene-flow-host/tests/test_layers.py` → `_CLEAN_PLANT` and `_VIOLATIONS`, its row in `devscene-flow-host/README.md` → `## The layers`, and its `__init__.py` docstring rule (`devscene-flow-host/README.md` → `## The layers`). |
| A record reader | Its `Final` name constants in its own module, a docstring naming the bash reader it reads as, and a `RecordError` case per unreadable shape asserting the exact message (`devscene-flow-host/src/devscene_flow_host/records/config.py`; `devscene-flow-host/tests/test_config.py`). |
| A runtime dependency | Its `[project] dependencies` entry; an `_IMPORT_NAMES` entry where its import name differs (`devscene-flow-host/tests/test_boundary.py` → `_IMPORT_NAMES`); and a re-lock, `bash scripts/python-service.sh --package devscene-flow-host lock` (`devscene-flow-host/README.md` → `## The lock follows GraphScene`), because `provision` syncs and every gate 13 leg runs against the lock as it stands (`docs/development.md` → **Gate 13**, `uv run --frozen --no-sync`, `uv sync --frozen`). |
| A test file | The header `.claude/context/conventions.md` → `## The testing bar` requires. |
| A test-support module | Its own `<snake_case>.py` beside the tests, imported by module name, with a docstring stating its rule (`devscene-flow-host/tests/requirement_names.py`). |

## One example from this layer

> `devscene-flow-host/src/devscene_flow_host/host/predicates.py` answers GraphScene's `PredicateHost` without guessing: `_resolve` returns a boolean or the reason there is none, `answer` passes on only a boolean, and `refusal_reason` passes on only the reason. It re-reads `devscene.config.json` and the flow-progress ledger through `records` on every call, and builds `PHASE_PREDICATE` from `devscene-flow-host/src/devscene_flow_host/records/config.py` → `PHASES` rather than restating the phase list.
