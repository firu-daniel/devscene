# The review sweep

> **Read this when:** you are the end-of-branch reviewer running the deterministic sweep over the lines a branch adds to this repository, or the analyze pass refreshing these rows from the conventions documents and the code. **Skip when:** you are a per-unit implementer or reviewer; neither loads this file.

**Purpose.** The escape classes this project's end-of-branch review sweeps for: the ways a change can bypass a single owner or a mandated construct that `.claude/context/conventions.md`, `.claude/context/cli.md`, `.claude/context/plugin.md`, `.claude/context/docs-retrieval.md`, `.claude/context/graphscene.md` and `.claude/context/devscene-runtime.md` state. Each row below is one class: a regex the sweep applies to the lines a branch adds under the paths the row covers, outside the sites it exempts. The reviewer then verifies every hit in context against the owning layer's conventions document.

**How the rows are written and read**

- The rows sit in the one table directly under the exact heading `## Sweep rows`.
- The table's header row is exactly `| Escape class | Regex | Covers | Exempts | A hit is a candidate for |`, followed by its separator row and then one row per escape class.
- The table ends at the first line that does not begin with `|`.
- `Regex` is exactly one backtick code span holding a POSIX extended regular expression, the dialect `grep -E` reads. A literal `|` inside it is written `\|`, and a regex cannot contain a backtick.
- `Covers` is one or more code-spanned repo-relative paths separated by `, `. Each is a `layers[].path` value or a path beneath one, and `.` is the whole repository.
- `Exempts` is code-spanned repo-relative paths or git pathspec globs separated by `, `, or the single character `—` for none.
- The last cell is prose.

A hit is a lead to verify in context, never a finding by itself. The rows are maintained by you, by hand or with the command in the block that follows.

```
/devscene:analyze sweep
```

A lesson in the lessons ledger is not a row. The rows are read as the default branch commits them, so an edit made on a branch takes effect once it is merged.

## Not determined

These are accepted limits of a table of regexes over added lines, plus two open questions.

- **A class with nothing to verify a regex against has no row.** A row's regex must match a real occurrence inside its `Covers`, and the probes for these matched none: a shell shebang other than `#!/usr/bin/env bash` outside the excluded paths; a third-party mocking framework or a stubbed `console` in `cli/test`; an exact line-number citation in `plugin`; the state-directory literal `harness-runs` in `plugin`; an agent `model:` other than `inherit`; a relative import in `docs-retrieval-service/src`; a process exit (`sys.exit`, `SystemExit`, `os._exit`) outside `cli.main` in `docs-retrieval-service/src`; a `logging` import or an async test plugin in `docs-retrieval-service` or `graphscene`; a `devscene` name or `devscene.config.json` under `graphscene/src/graphscene`, which `graphscene/tests/test_boundary.py` enforces already; a `logging` import, an async test plugin or a mocking aid in `devscene-runtime`. A class gains a row when a real occurrence exists to write its regex against.
- **A rule about a file's presence, position or absence, about text outside the diff, or about run-time behaviour a line does not show, has no row**, because the row format cannot express it: a frontmatter fence opening an instruction file; a `README.md` in `plugin/agents` or `plugin/commands`; an agent definition with no `tools:` line; a configuration key missing from one of its four places; the commit-message policy; `__version__` moved without `pyproject.toml`'s `version`; a model-pin bump on one retrieval path only; a `graphscene` or `devscene-runtime` runtime dependency without its `_IMPORT_NAMES` entry; an import of an undeclared distribution under `devscene-runtime/src/devscene_runtime`, which `devscene-runtime/tests/test_boundary.py` enforces; a `from graphscene import` naming something outside `graphscene.__all__`; a hand edit to `devscene-runtime/uv.lock` rather than a re-lock; a change to `graphscene/pyproject.toml` → `[project] dependencies` without the `devscene-runtime` re-lock; a stdout write under `serve-mcp`. Enforcing one takes a check outside this table, such as a `treeGuards` test.
- **Whether `node:test`'s built-in `t.mock` is admitted in `cli/test` is not stated**, so it has no row: `.claude/context/conventions.md` → `## The testing bar` says the `cli` suite has no mocking framework and lists its substitutes without `t.mock`, and `cli/test/upgrade-inputs.test.mjs` uses `t.mock.method(process, 'kill', …)`. What would settle it: that heading stating whether `t.mock` counts as a mocking framework; a `t\.mock\.` row over `cli/test` follows if it does.
- **A branch-name literal in `plugin` has no row.** The bare words `main` and `dev` are ordinary prose there ("main checkout", "dev server"), so a regex on them is no usable lead.
- **Whether the service image's own listen host is inside the local-only rule is not stated**: `.claude/context/docs-retrieval.md` → `## What this layer is, and what it is not` names published compose ports and the `serve-http` default, and `docs-retrieval-service/Dockerfile` → `CMD` passes `--host 0.0.0.0`, so the **Bind off loopback** row does not cover the `Dockerfile`. What would settle it: that rule, or the `docs-retrieval-service/compose.yaml` header, stating whether the in-container host is exempt.
- **A Python toolchain invoked outside `scripts/python-service.sh` has no row.** `.claude/context/conventions.md` → `## The stack, in the words the rules below use` says nothing invokes `uv`, `ruff`, `mypy` or `pytest` directly, but every probe hit outside `scripts` is legitimate — prose naming what the wrapper runs, `docs-retrieval-service/Dockerfile`'s image build, the command lines `cli/src/detect/presets.ts` derives for adopters — so a regex on those names is no usable lead.
