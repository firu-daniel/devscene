# cli review — ### 1. Replace the watcher tunable `PLANNING_DRIVER_PLUGIN_DIR` with a `devscene.config.json` key so remote jobs take script-driven planning too — iteration 0

## Should Fix
1. **The shell mirror does not normalise the root the way `pluginRuntimeRoot` and the profile grant do, so the job-mode dedupe can miss** — `cli/templates/scripts/lib/harness-run-lib.sh` (`hr_plugin_runtime_root_var`) — "*) HR_PLUGIN_RUNTIME_ROOT=\"${location%/}/$relative\" ;;"
   `cli/src/machine/plugins.ts` → `pluginRuntimeRoot` returns `join(location, relative)`. That collapses interior `.` and `..` segments and repeated separators. `init --plugin-root-entries` then writes the root into `permissions.additionalDirectories` through `normalizedRoot` (`cli/src/generators/profileEntries.ts`, `join(path, '.')`). The shell mirror only strips leading `./` prefixes and one trailing `/`, from `relative` and from `location`. Take a manifest `source` such as `./a/../plugin` or `plugin//`, or an `installLocation` that ends in `//`. The derived string is then a different spelling of the same directory. `spawn_engine`'s comparison in the block that starts "With the pilot on, the plugin's runtime root is a session root too" (`"${listed_dir%/}" = "${PLANNING_DRIVER_PLUGIN_ROOT%/}"`) misses it. `PD_PLUGIN_DIR_ADDED` stays empty, and in a job every node session passes `--add-dir` of the root twice: once through `extra_dir_args` and once from `pnl_agent_flags`. That is the duplicate item 5 of the task file asks the dedupe to prevent. Nothing breaks, because both spellings name one directory. But the header now calls the function a mirror of `pluginRuntimeRoot` ("Change the selection there and here together"), and `cli/test/plugin-runtime-root-lib.test.mjs` only checks parity on the already-normal `./plugin` shape and on one trailing slash on `installLocation`. Confirmed by reading only, not by a probe: I compared the two functions' string handling and the `normalizedRoot` definition.
   **Fix:** Normalise the joined path the way `join` does before assigning it. Collapse repeated `/`, drop `.` segments, resolve `..` segments lexically and strip the trailing `/`, in a small loop over the `/`-split segments. Alternatively, do the dedupe comparison in `spawn_engine` on a normalised spelling of both sides. Then add a `cli/test/plugin-runtime-root-lib.test.mjs` case with a non-normal manifest `source` (for example `./a/../plugin/`), held against the compiled `pluginRuntimeRoot` like the existing cases.
