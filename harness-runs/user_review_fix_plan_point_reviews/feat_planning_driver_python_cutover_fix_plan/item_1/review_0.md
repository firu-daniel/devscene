## Should Fix

1. **The live path's stated fallbacks and the executor's close-on-every-path rule have no case** — `devscene-flow-host/src/devscene_flow_host/host/node_sessions.py` (`NodeSessions._format_live`) — "self._live_formatting = False"; `devscene-flow-host/src/devscene_flow_host/host/claude_executor.py` (`ClaudeExecutor.run`) — "live.close()"
   The module docstrings now state four rules that no test reaches: a formatter that cannot be started on the live path is narrated **once** and live formatting stops; a formatter whose stdin breaks (the suite's default `true`) is dropped **silently**; `ClaudeExecutor.run` closes the `LiveStream` on a launch error and on cancellation; and it closes it **before** `usage_sink.record`. Both new cases in `tests/test_node_sessions.py` use `formatter="cat"` over a healthy session, and `tests/test_claude_executor.py` is untouched, so a regression that narrates on every chunk, raises `BrokenPipeError` out of a session, or skips `close` on cancellation (losing the unterminated remainder from the log) would pass the suite. The task plan's test list did not ask for these cases, which is why this is not graded Must Fix.
   **Fix:** In `tests/test_node_sessions.py`, add (a) a case with `formatter` set to a name not on `PATH` that opens two live streams, writes a complete line to each, and asserts the recording narrator received exactly one `the formatter '<name>' could not run: …` line and that both node files hold their bytes; (b) a case with `formatter="true"` that writes several complete lines through a live stream and then calls `close()` on it and on `sessions`, asserting no exception and no narration. In `tests/test_claude_executor.py`, add a case with a recording `StreamSink` stand-in whose `LiveStream.close` appends `"close"` to a shared list and whose usage sink appends `"record"`, asserting the list is `["close", "record"]` for a normal session and `["close"]` for a launch error (`command` naming a missing executable) and for a run cancelled while a `wait_for` step holds the fake open.

2. **The run log's order between a node's formatted lines and its stderr tail / narrations is no longer guaranteed, and the docstring does not say so** — `devscene-flow-host/src/devscene_flow_host/host/node_sessions.py` (`NodeSessions._record_usage`) — "_append(self._log_path, (tail if tail.endswith(\"\\n\") else tail + \"\\n\").encode(\"utf-8\"))"
   Before this change `_format` ran the formatter synchronously (`subprocess.run`), so a node's formatted lines were in `<branch>.log` before its `stderr_tail` and its `WITHHELD_LINE` narration (which `commands/planning_driver.py` → `_narrator` appends to the same log). On the live path the formatted lines are written by a long-lived formatter process asynchronously, while the tail and the narration are appended directly by this process, so the node's last formatted lines (its `result` event) can land after its stderr tail or after the withheld-tools narration for its own seq. Nothing breaks, but a reader of the log can see a node's diagnosis before the output it explains, and the module docstring's rule ("in order: … the formatter …; a non-empty `stderr_tail` appended to the log") still reads as ordered.
   **Fix:** Add a line to `node_sessions.py`'s *"Deliberately not covered"*: the order in the log between the live formatter's lines and lines this module or the narrator append directly (a stderr tail, `WITHHELD_LINE`, the driver's narrations) is not guaranteed, since the formatter writes asynchronously; and qualify the rule's "in order" sentence to the record-only path. (Alternatively, if order matters, the stderr tail could be passed through `_format_live` as a non-JSON line is a no-op for `autonomous-format-stream.sh` — but that would drop it from the log, so documenting is the smaller change.)
