# graphscene review — 2. The undelivered re-dispatch observation and its narration line were dropped — iteration 0

## Should Fix
1. **`Launch`'s docstring says a fresh breaker gives 0, but the second pass of the same set gives 1** — `graphscene/src/graphscene/model/run_control.py` (`Launch`) — "0 for a host that drives `execute_set` with a fresh breaker"
   The value is 0 only on the **first pass** of the first set a fresh breaker drives. In that same set, a pass that follows an undelivered pass is cleared with `breaker.strikes == 1`, so its rows carry 1. The unit's own new test shows this: `test_each_row_carries_the_strikes_its_pass_was_cleared_with` hands a fresh `UndeliveredBreaker()` to the first `_execute`, and that set's second row is `Launch(2, "a", "a-agent", 1, 3, Completed("pass"), 1)`. A host author who reads the docstring could assume the field is always 0 under a fresh breaker. The wording is the text `finding_2.md` prescribed, so the implementer followed the plan. The defect is still in durable code text. It is a doc comment, so under `finding_grades.md` it cannot be a Must Fix on its own.
   **Fix:** Replace the clause with: "0 on the first pass a fresh breaker clears, and for a `Launch` a host constructs without it."
