### 5. `doctor` and the upgrade report tell the adopter to pin the CLI back

**File:** `cli/src/doctor/checks.ts` (`PLUGIN_CLI_VERSION_CHECK`) — "from the CLI of the plugin's version"

**Also changes:** `cli/src/upgrade/report.ts` (`upgradeReport`, `UpgradeReportInput`) — "from the CLI of the plugin's version."; `cli/src/upgrade/initUpgrade.ts` (`runInitUpgrade`) — "pluginCliCommand"; `cli/test/doctor-upgrade-drift.test.mjs`; `cli/test/upgrade-report.test.mjs`; `cli/test/init-upgrade.test.mjs`.

**Depends on Findings 1 and 3.** Finding 1 adds `cli/src/machine/pluginCliVersion.ts`, exporting `PluginCliMismatch`, `pluginCliMismatch(pluginVersion, cliVersion)` and `pluginCliMismatchWarning(mismatch)`, the one producer of the complete warning sentence: `The installed plugin is version <plugin> and this CLI is version <cli>. <the remedy with its first letter capitalized>.` Neither `cli/src/doctor/checks.ts` nor `cli/src/upgrade/report.ts` assembles or capitalizes that sentence. `pluginCliMismatchWarning` reads this package's manifest (through `pinnedCliCommand('latest')`, `ownManifestString('name')` and `ownManifest`), and the module header of `report.ts` states that `upgradeReport` reads no file, so the report receives the finished sentence as an input and does not import `cli/src/machine/pluginCliVersion.ts`. Finding 3 leaves `runInitUpgrade` handing the report the plugin version only when `target.selfAdopted` is true.

Both messages currently send the adopter to `npx devscene@<plugin version> init --upgrade`, which can pin the CLI back to an older plugin. They must follow the same rule as the refusal: update whichever half is older. The doctor check stays a warning and keeps its two pass cases.

**Fix:**

- [ ] In `PLUGIN_CLI_VERSION_CHECK`, compute `pluginCliMismatch(pluginVersion, cliVersion)`. Keep the unreadable-version and matching-version `pass` lines as they are. For a mismatch, return `warn(pluginCliMismatchWarning(mismatch))`.
- [ ] Rewrite the check's doc comment: the remedy now updates whichever half is older, and the sentence saying it pins the plugin's version goes. Remove the `pinnedCliCommand` use here only. The import stays, because other checks in the file use it.
- [ ] In `cli/src/upgrade/report.ts`, replace `pluginVersion` and `pluginCliCommand` on `UpgradeReportInput` with `pluginMismatchWarning: string | undefined`, documented as the `pluginCliMismatchWarning(mismatch)` value and set only for a self-adopted run. Replace the old warning: when `pluginMismatchWarning` is set, `upgradeReport` pushes that string unchanged. `report.ts` imports nothing from `cli/src/machine/pluginCliVersion.ts`. `cliVersion` remains only if something else in the function still reads it; remove the field if nothing does.
- [ ] In `runInitUpgrade`, import `pluginCliMismatchWarning`, pass `pluginMismatchWarning: target.selfAdopted && mismatch !== undefined ? pluginCliMismatchWarning(mismatch) : undefined`, and remove the `pinnedCliCommand(pluginVersion)` argument. `cliCommand: pinnedCliCommand(cliVersion)` stays, because the watcher restart line needs it.
- [ ] In `cli/test/doctor-upgrade-drift.test.mjs`, update the "warns about a plugin of another version" case. With the older `OTHER_VERSION`, assert the line contains the complete sentence ``The installed plugin is version ${OTHER_VERSION} and this CLI is version ${cliVersion}. Update the plugin with `claude plugin update devscene@devscene`, restart any open session, then run `npx <package>@latest init --upgrade`.``, and no `@${OTHER_VERSION}`. Add a plugin newer than the CLI: the line contains ``The installed plugin is version <plugin> and this CLI is version ${cliVersion}. Run `npx <package>@latest init --upgrade`.`` and not the plugin update. Keep the matching-version pass.
- [ ] In `cli/test/upgrade-report.test.mjs`, update the `report` helper defaults and the three cases using `pluginVersion` and `pluginCliCommand`, including the plain-ASCII case, which supplies a plain-ASCII `pluginMismatchWarning`. Assert that a supplied `pluginMismatchWarning` string appears exactly once in `warnings` in both modes, and that no warning appears when the field is `undefined`. The exact sentences are covered by Finding 1's `cli/test/plugin-cli-version.test.mjs` cases and by the `cli/test/doctor-upgrade-drift.test.mjs` and `cli/test/init-upgrade.test.mjs` bullets of this finding.
- [ ] In `cli/test/init-upgrade.test.mjs`, tighten Finding 3's self-adopted case to assert the forward remedy and the absence of an `@<plugin version>` pin.
