## Must Fix
1. **`ExecutionLimits.undelivered_sets` has no consumer: the host-supplied breaker limit never reaches the breaker** — `task_4_plan.md` (with `task_2_plan.md`)
   The index's `## Context` decision says the limits are the host's, carried by `ExecutionLimits(..., undelivered_sets=3, ...)`, and Task 1 declares and validates that field. No component then reads it. Task 2's `UndeliveredBreaker.__init__(self, limit: int)` takes its own integer, and `clear_set` reads only `dispatch_cap`, even though Task 2's `**Depends on:**` claims to use `undelivered_sets` "exactly as follows". Task 4's `execute_set` takes both a ready-built `breaker` and `limits`, and decides the trip only through `breaker.observe(...)` / `breaker.tripped`. Nothing in its Work reads `limits.undelivered_sets`, and nothing checks that the two values agree. So the plan ships two sources of truth for one limit, and the one the Context names as the host's interface has no effect.
   **Raised against:** "`UndeliveredBreaker`, with `observe(undelivered: bool) -> int` and `tripped`" (task_4_plan.md), alongside "`ExecutionLimits`: `dispatch_cap: int | None` and `undelivered_sets: int`, both already validated" (task_2_plan.md)
   **Must hold:** Each host-supplied limit in `ExecutionLimits` has exactly one consumer named in a task's Work that makes it take effect. Alternatively, a limit is not carried in `ExecutionLimits` at all, and the index's Context decision says where it is supplied instead. Either way, `execute_set` cannot run with a breaker limit that differs from the limit the host passed.
   **Class:** Wrong build
   **Failure:** If a host (or Task 6's suite) calls `execute_set(..., breaker=UndeliveredBreaker(3), limits=ExecutionLimits(undelivered_sets=2), ...)` as the plan builds it, the run halts with `"undelivered"` only after the third consecutive undelivered set, not the second, because no task's code reads `limits.undelivered_sets`.
   **Fix:** In `task_4_plan.md`, make `execute_set` the consumer. Either (a) it builds or validates the breaker from `limits.undelivered_sets`, for example by refusing with an exact `ValueError` text when `breaker.limit != limits.undelivered_sets`, with a test case asserting that text; or (b) drop `undelivered_sets` from `ExecutionLimits` in `task_1_plan.md` and the index's Context decision, and state that the breaker's limit is supplied at `UndeliveredBreaker` construction with GraphScene's default of 3. Correct `task_2_plan.md`'s `**Depends on:**` to name only the `ExecutionLimits` fields it actually reads, and restate the chosen contract on both sides (`task_2_plan.md` / `task_4_plan.md`, and `task_6_plan.md`'s restated call).
