## Should Fix

1. **`task_2_plan.md` — "a missing … state directory" is listed as an exit-4 case, but the store creates it.** The third Work bullet's exit-4 list reads *"a missing graph, state directory or resume file"*. `graphscene/src/graphscene/adapters/state_file.py` → `FileStateStore.lock` runs `self._lock_path.parent.mkdir(parents=True, exist_ok=True)` before taking the lock, and `write` does the same. So `start` / `next` given a state path in a directory that does not exist create the directory and exit `0` or `3`. `current` does not lock: `read` returns `None` on `FileNotFoundError`, so it refuses with `"no walk has started"` and exits `3`. The docstring Task 2 writes, and the README section Task 3 builds from that docstring, would both describe an exit that does not happen. Drop "state directory" from the list, or state the real behaviour. No case asks the implementer to test it, so no step fails.

2. **`task_1_plan.md` — the "Every action" case takes its expected value from `state_to_json`'s output.** That case compares `step_document(action)` with the `pending` object of `json.loads(state_to_json(state))`. Two documents say expected values are hand-written and never taken from the code's output: `.claude/context/graphscene.md` → `## Tests`, and the module docstring of `graphscene/tests/adapters/test_walk_json.py` (*"never taken from the codec's output"*). This task's own Verification bullet makes the same promise for every new case, so the plan contradicts itself. The equivalence check is the guard for the first `Top risks:` entry and is worth keeping. Either also assert against a hand-written expected object for at least one variant, or have the extended header name this case as a deliberate exception and say why.

3. **`task_4_plan.md` — the closure re-run in Verification can fail because of text Task 3 adds.** The first Verification bullet re-runs derivation entries A and B and requires every hit to be a register row. Task 3 adds `graphscene/README.md` → `## The command line`. If that section says "thin command line" or "command-line entry point", it gives entry A a new hit that matches no row; rows 6 and 7 anchor on `## The layers`. The Task 4 implementer cannot edit the story index, so the check fails on a site the branch itself created. Also, the register is not in the index's `## Context`, which is the only index text a per-task file may rely on. Limit the check to the two rows this task owns, or say that hits inside the section Task 3 adds are expected.

4. **`task_2_plan.md` — the lone-surrogate case runs in-process only (`harness-runs/lessons.md` → `## Ports and parallel implementations`: *"carries it through every transport's serializer to the client"*).** The ASCII case writes to an `io.StringIO`. The one subprocess case runs `check` on a valid graph and carries no surrogate. Asserting the output is ASCII does make any encoder safe in principle. Still, giving the subprocess case (or a second one) a surrogate-bearing `--entry`, passed as bytes through `os.fsencode`, would show the real process stdout carrying it, which is what the lesson asks for.
