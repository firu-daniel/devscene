- **`task_3_plan.md`, Verification → the third check: it runs the real `scripts/python-service.sh`, and it never shows that a failed `provision` fails the line.**

That wrapper is the script `scripts/run-gates.sh` runs as gate 13. Task 1's own file says "This task runs none of the wrapper's sub-commands, because each one is a gate-13 leg". That makes this check sit awkwardly with `unit_loop_core.md` → `## The test-run rule` points 1 and 4 ("a gate script"), even though `provision` is not a leg and writes nothing without `uv`.
  - **It leaves the failure path untested.** The plan's own claim, "a failed sync still fails the bootstrap (Task 1's exit `1`)", is never exercised against the configured line.
  - **The fix.** Replace the check with a third scratch checkout whose `scripts/python-service.sh` is a stub. It carries the `# PROVIDES: provision` line and exits with a status taken from its environment. Run the checker against it twice: once where the stub exits `0` (the line exits `0`), once where it exits `1` (the line exits `1`). That covers the marker arm and status propagation without running the real wrapper. Task 4 already pins the real wrapper's no-`uv` `SKIPPED` exit `0`.
