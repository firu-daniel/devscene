### Task 1 — Add `probe` and `check` to `scripts/python-service.sh`, placing its root with `hr_script_root`

**Goal:** Give the one Python wrapper two new verbs. `probe` runs one `.py` file from `<state_dir>/scratch/` inside a package's synced environment. `check` runs every package-table row's `lint` and `typecheck` legs and grades the result. In the same change, the wrapper places its repository by the run library's `hr_script_root`, so both verbs work inside a bubblewrap sandbox.

**Where this task stops.** This task changes `scripts/python-service.sh` alone. **Task 2** makes `scripts/typecheck.sh` call `check`. **Task 3** pins both verbs in `cli/test/python-service.test.mjs`. **Task 5** writes the agent-facing route that resolves to `probe`. **Task 7** documents both verbs in `docs/development.md`. `scripts/scratch-run.sh`, `cli/templates/scripts/scratch-run.sh` and both copies of `harness-run-lib.sh` are not edited.

- [ ] **`probe <scratch-file> [args...]`**, with the usual optional leading `--package <dir>` (default row unchanged). This is the contract Tasks 2, 3, 5 and 7 rely on:
  - **The path is relative to the repository root, or absolute**, unlike every other verb's package-relative paths. It is judged **before** the `cd` by `hr_scratch_path_var "$repo_root" "$1"`, the test `scratch-run.sh` applies. A missing argument, a first argument starting with `-` (no `-c`, no inline program), any `HR_SCRATCH_WHY` other than empty, a basename not ending in `.py`, and a target that is not a readable regular file each print one stderr line `python-service: probe: <reason>`, call no `uv`, and **exit 2**. The reasons are worded after `scratch-run.sh`'s for the same `HR_SCRATCH_WHY` keyword.
  - **The library not readable** prints `python-service: probe: cannot read <path> — refusing to run anything` and **exits 1**.
  - **Not provisioned** is `require_env`'s existing line and **exit 3**.
  - **The run**, from the package directory with `export_locations` applied: `exec uv run --frozen --no-sync --no-cache python "$target" "$@"`. Remaining arguments are forwarded verbatim and resolve against the package directory. **The file's own exit status passes through unmodified.** This is the one verb exempt from the contract's map-to-`1`, so a refusal is told apart by its `python-service: probe:` stderr line, as `scratch-run.sh`'s header states for its own codes.
- [ ] **`check`**, which takes no argument and no `--package` (either is exit `2` with `usage`, as `provision` refuses them). For every row of `PACKAGES`, in table order, it runs this script's own `lint` and then `typecheck` for that row, as `bash "$script_dir/python-service.sh" --package "$row" <leg>`, so each leg is exactly the gate leg. After each leg it prints one stdout line, `python-service: check: <row> <leg> PASS`, `FAIL` or `BLOCKED`: exit `0` is `PASS`, exit `3` is `BLOCKED`, any other is `FAIL`. **It exits `1` when any leg failed, `3` when none failed and at least one is `BLOCKED`, and `0` when all passed.** It always runs every leg, even after a failure. With no `uv` on `PATH`, every leg is `BLOCKED` and `check` exits `3`.

No record the session cannot write tells that caller from an agent, and an environment variable is not such a record (`harness-runs/lessons.md` → `## Trust checks`, *"An unsandboxed script takes its mode … from a record the session cannot write"*).
