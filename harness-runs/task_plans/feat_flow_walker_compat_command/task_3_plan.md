### Task 3 — Render a `HostStep` as `flow-walker.sh`'s `key: value` output in `commands/render.py`

**Goal:** The `commands` layer's first module: turn the host's `HostStep` into exactly the stdout `flow-walker.sh` prints for the same action — every key, its order, the actions and the passed-through `skip:` / `round:` / `ledger:` / `report:` / `refused:` lines — so the callers that parse it (`cli/templates/scripts/lib/planning-driver-lib.sh`, `planning-node-lib.sh`, `plugin/instructions/task_plan_writing_instructions_core.md`, `plugin/instructions/user_review_fix_plan_writing_instructions_core.md`) read it unchanged.

**Depends on:** Task 1, which adds `HostStep.revision_findings: tuple[str, ...]` (default `()`) — the kept non-round findings file, already cleared by the host whenever a round closes. This task applies the precedence: the findings files a step carries are `revision_findings` when non-empty, otherwise the `detail` of each `GateRecord` in the action's `closed_round` that has one, in that tuple's order (GraphScene's, the round's `gates` order). `HostStep.action` is a GraphScene `Step` or `host/round_gates.py` → `RefusedWait(round, refusal, pending)`; `HostStep.refusals` is the `refused:` lines it brings.

**Where this layer stops.** `render` never sees a `Refused` — Task 5 turns one into an exit-1 line before rendering — and decides no exit status. It reads records only through the host and `records` functions named below, and imports GraphScene only from `graphscene`.

**The contract this task produces:** `devscene_flow_host.commands.render.render(step: HostStep, *, graph: FlowGraph, repo_root: Path, state_dir: str, branch: str) -> str` — the whole stdout, one `\n`-terminated line per key, plain ASCII, raising `ValueError` with a one-line message for a fault bash reports as exit 2 (below). Task 5 calls it after every non-`Refused` step.

**The grammar** (`cli/templates/scripts/flow-walker.sh` → the header's `OUTPUT`, and `render_block`, `render_set`, `record_in_set`, `take_binding`, `render_terminal`):

- **A dispatch block**, in this order: `action: dispatch`, `node: <node>`, `agent: <agent>`; `prompt: <variant>` when the node declares `prompts` (`Dispatch.prompt`, or `initial` when it is `None`; a variant outside the node's `prompts` raises `ValueError("graph gives '<node>' the unknown prompt variant '<v>'")`); for a round's **writer** (`host/reviewers.py` → `round_of_writer`) `arg.iteration: <Dispatch.round_number>`; on `prompt: revision` one `arg.findings_file: <path>` per findings file, or `ValueError("a revision of '<node>' is due and no findings file is recorded")` when there is none; for a round **gate** (`round_of_gate`) `arg.iteration: <round_number>` then `arg.review_mode: full|converging` from `Dispatch.converging` (no line when it is `None`); for any other node with a `findingsFolder`, `arg.iteration: <review_iteration(graph, repo_root, state_dir, branch, node)>`; then the passed-through lines; last `heartbeat: <template>  (#<total_dispatches>)` — two spaces before `(#`, the node's `heartbeat` with `{iteration}` replaced by `Dispatch.counters["iteration"]`, or by nothing when that counter is absent, as bash substitutes `counter.iteration`.
- **Passed-through lines**, in `passed` order: `SkipPassage` → `skip: <node> <status>`; `RoundPassage` → `round: <number> <VERDICT>` with the verdict upper-cased (`pass` → `PASS`); `LedgerPassage` → `ledger: <entry>`. A `refused:` line is `refused: <gate> attempt <attempt> of 3: <reason>` (`host/refusals.py` → `ROUND_FILE_ATTEMPTS`).
- **A set** (`DispatchSet`): one dispatch block per `Dispatch`, back to back; the set's `passed` lines and then one `refused:` line per `HostStep.refusals` entry go in the **first block only**, where a single dispatch carries its own.
- **A wait**: `action: wait`, `node: <round>`, then `recorded: <gate> <outcome>` for a `Wait` or `refused: …` for a `RefusedWait`, then `pending: <gate>` per pending gate.
- **A binding**: `action: binding`, `binding: <name>`, `node: <node>`, then `agent: <agent>` unless `agent` is `None` (a round node). An `Interrupt` adds `resume: <resume>`. A `Stop` adds `reason: <reason>`; when the reason is `cap`, one `findings_file: <path>` per findings file, `rounds: <node> <fail_count(repo_root / render_path(findingsFolder))>` per `round_counts` entry, the evidence lines from `read_index_evidence(repo_root / render_path(graph.paths[evidence]))` — `evidence: <abs index> ## Rejected findings` when that section exists, `evidence.open: <line>` per open entry, `evidence: <abs index> ## Scope register` when that section exists — and `summary: <summary>` when GraphScene gave one; then `held: <gate> <outcome>` per `Stop.held` record and one `refused:` line per `HostStep.refusals` entry. An `End` adds `report: <slot> <status>` per `End.reports` pair. Every binding ends with its passed-through lines.
