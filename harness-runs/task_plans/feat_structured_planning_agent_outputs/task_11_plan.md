### Task 11 — Read the validated return object in `planning-driver-lib.sh`, and bring the driver fixture's stub and suites to the return block

**Goal:** Make the planning driver read what Task 10's `pnl_reap` now prints — the validated return object — for every field it uses after a node ends, and make the stub agent CLI the driver suites share produce what a real node session produces: a `result` whose text ends in a return block valid against the real agent's `## Return schema`, and no `structured_output`.

**Depends on:** Task 10. The exact contract consumed from `pnl_reap`: it prints `kind=`, `class=`, `outcome=`, `findings=`, `return_file=`, `object_file=`, `cost=`, `duration_secs=`, `denials=`, `withheld=`, `reason=` (no `friction_file=`); `return_file=` names a file holding the whole `result` text and `object_file=` a file holding the validated object as compact JSON, both set only when the outcome was read as declared; a return that fails its block or schema is `kind=error class=infra`, retried like any infrastructure failure. And on Tasks 2–5's schemas, of which the driver reads: `` `task-plan-writer.tasks_count` ``, `` `task-plan-writer.questions` ``, `` `ui-tests-plan-writer.tests_count` ``, `` `ui-tests-plan-writer.reason` ``, `` `ui-tests-plan-writer.questions` ``, and the gates' `findings_file`, which `pnl_reap` already prints as `findings=`.

**Where this task stops.** The watcher suite's own stub is Task 12's. The walker, the retry bound `PD_MAX_ATTEMPTS`, the undelivered path and every commit and park the driver makes are unchanged; only what the driver reads after a reap, and the park body built from questions, change.
