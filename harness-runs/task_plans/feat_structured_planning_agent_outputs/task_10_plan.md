### Task 10 — Drop `--json-schema` from `planning-node-lib.sh` and decide a node's outcome from its return block validated against the agent's `## Return schema`

**Goal:** Make the planning driver's node library stop depending on `--json-schema` being applied under `--agent`: load each planning agent's own `## Return schema` from the pinned plugin, take the return object out of the `result` event's text, validate it against that schema in jq 1.5, and derive the node's outcome from the validated object — with the planning graph still the one owner of which outcomes a node may have.

**Depends on:** Tasks 2–5, which give each of the six agents a `## Return schema` section — exactly one fenced block opened by a line that is exactly ```` ```json ````, directly after `## Output contract` — in the dialect of `plugin/instructions/agent_return_contract.md` → `## The return schema`: top level `$schema`, `title`, `description`, `type: "object"`, `oneOf`; each variant `type: "object"`, `description`, `properties`, `required` (always including `outcome`), `additionalProperties: false`; `properties.outcome` a `{ "const": … }`; every other property `type` ∈ `string` / `integer` / `boolean` / `array`, with `description`, `const`, `enum`, `minLength`, `minimum`, `minItems`, `items` (`{ "type": "string" }`, optional `minLength`). And on the return block of `## The return block`: the last fenced block opened by a line that is exactly ```` ```json ````, holding one JSON object, with nothing but whitespace after its closing fence. The measured fact this relies on is the task prompt's fourth table row: under `--agent` the `result` event's `result` is the agent's own reply text, fences included, and carries no `structured_output`.

**Where this task stops.** This task changes what `pnl_reap` decides and prints. `planning-driver-lib.sh`, which reads those lines (`pd_reap_one`, `pd_ret_value`, `pd_ask_park`), and the driver suites' stubs are Task 11's; the watcher suite's stub is Task 12's. Those suites — `cli/test/planning-driver-walk.test.mjs`, `cli/test/planning-driver-control.test.mjs`, `cli/test/watcher-planning-driver.test.mjs` — are expected to fail between this commit and Task 12's (story index `## Context`), and this task edits none of them. `cli/templates/scripts/remote-run.sh`'s own `--json-schema` session runs without `--agent` and is untouched.
