## Should Fix

1. **`task_1_plan.md` (and the story index `## Context`, *What is decided*) — the format-4 source is placed in `cli/templates/`, a tree whose stated content is the files `init` writes into an adopting repository.** `.claude/context/cli.md` → `## What this layer owns, and what it is not` says the layer owns *"`cli/templates/` (the files `init` writes into an adopting repository)"*. `.claude/context/conventions.md` → `### Where a new responsibility goes` sends *"a file a future adopter receives"* to `cli/templates/`. `cli/templates/README.md` maps each subdirectory to an *"Adopter-side home `init` writes to"*, with `scripts/` → the configured `scriptsDir`. `cli/templates/scripts/flows/task_plan_writing.v4.graph.json` has no adopter-side home: the plan states that `init` never writes it and that `OUTER_LOOP_SCRIPTS` carries no row for it. It is this repository's own authoring source, read only by the root `general`-layer tools of Tasks 4 and 5. The cited justification is the task prompt's lead *"The harness's own vocabulary lives with the harness's graphs (`cli/templates/scripts/flows/task_plan_writing.graph.json`)"*. That prompt marks its leads as *"starting points … not requirements"*, so the lead puts the vocabulary near the harness's graphs but does not override the tree's stated contract. The cost is concrete: the file ships in the npm tarball (the plan accepts this), and `cli/templates/README.md`'s description of the tree becomes false, while Task 1 amends only `cli/templates/scripts/README.md`. This is graded Should Fix rather than Must Fix for three reasons: no step in the plan fails, no test enumerates the template tree against `OUTER_LOOP_SCRIPTS` (checked: `cli/test/outer-loop-scripts.test.mjs`, `init.test.mjs`, `watcher-main-anchor.test.mjs`, `shipped-scripts-mktemp.test.mjs`), and the planned cutover would make the file one adopters receive.
   **Fix (suggested):** either put the v4 source outside `cli/templates/`, in a root `general`-layer location beside its only readers (`scripts/generate-flow-graph-v3.mjs`, the `validate:graphscene-schema` npm script), or keep it where it is and have Task 1 also add a sentence to `cli/templates/README.md` naming the one file in the tree that `init` does not write, and why it is there until the cutover.
