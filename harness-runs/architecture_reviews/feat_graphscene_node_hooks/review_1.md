## Must Fix
1. **`task_11_plan.md` has `host/agent_prompts.py` open and read the clarification question and answer files itself, which puts a record read in `host` instead of `records`.** This violates `.claude/context/devscene-flow-host.md` → `## The internal layers` (*"Reading a record into a value is `records`; answering a GraphScene protocol over it is `host`"*) and `## Errors` (*"`RecordError` is the one anticipated failure of reading a repository record"*).
   Task 9 gives `records/clarifications.py` the pair *paths* only, and says it never opens a file's text. Task 11's builder then reads each pair's question and answer file under `repo_root`, scans it for `=== END UNTRUSTED DATA` and copies its text into the prompt. The contract says so outright: *"The builder reads disk only through `RevisionFindingsStore`, `review_iteration` and the pair files"*. The plan's other repository reads all sit in `records`: Task 8 put the core document's read in `records/prompt_blocks.py` for this reason. Today `host` reads only the records it keeps itself (`host/printed_reads.py`, `host/refusals.py`, `host/revision_findings.py`). Because the read happens in `host`, the plan also gives it no `RecordError` shape. A missing pair file or one that is not UTF-8 would surface as a raw `FileNotFoundError` or `UnicodeDecodeError`. Every other unreadable record in this package gives a one-line `RecordError` naming the file.
   **Raised against:** "The builder reads disk only through `RevisionFindingsStore`, `review_iteration` and the pair files, and keeps nothing else between calls."
   **Must hold:** Reading a clarification question's or answer's text is a `records`-layer function that raises `RecordError` with a one-line message for a missing or non-UTF-8 file. `host/agent_prompts.py` gets pair text only by calling it and opens no repository file of its own beyond the host-kept `RevisionFindingsStore`.
   **Class:** Broken contract
   **Failure:** If the implementer of Task 11 follows its contract as written, then `host/agent_prompts.py` calls `read_text` on `repo_root / pair.question` and `repo_root / pair.answer` itself. A planted non-UTF-8 answer file then makes `CorePromptBuilder.__call__` raise `UnicodeDecodeError` instead of a `RecordError` naming the file, and a record read sits in the `host` layer.
   **Fix:** Add a reader for one pair file's text to `records` and have the builder call it. Either extend `task_9_plan.md`'s `records/clarifications.py` contract with, for example, `read_pair_text(repo_root: Path, rel: str) -> str`, or give the reader its own new `records` module in Task 9. It raises `RecordError(f"the clarification file '{rel}' cannot be read")` on `FileNotFoundError` and `RecordError(f"{path}: not UTF-8 text")` on a decode failure, and lets any other `OSError` propagate. Add one test case per message to `tests/test_clarifications.py`. Keep `read_answered_pairs` exactly as it is, never opening an answer file, and state in the docstring that `read_pair_text` is called only for pairs the caller has kept (Task 14 leaves out `Phase G` origins). In `task_11_plan.md`, add that function under **Depends on:** (Task 9). Change step 5 and the closing sentence so the builder gets each pair file's text through it, and add a builder case in which a non-UTF-8 pair file propagates that `RecordError`.
