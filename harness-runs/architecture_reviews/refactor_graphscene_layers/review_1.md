## Should Fix
1. **`task_1_plan.md` — `adapters/schema.py`'s docstring states the rule it holds but not what it owns** (`.claude/context/graphscene.md` → `## What accompanies a new module`, first bullet; `## Naming and layout`, third bullet). This is carried from round 0 and still open. The module takes only *"the ECMA-262 paragraph of `loader.py`'s docstring"*. That paragraph (`graphscene/src/graphscene/loader.py`, *"A schema `pattern` is matched as ECMA-262, as `ajv` matches it…"*) covers pattern translation. It never says that the module owns validating a parsed graph against the shipped format-4 schema, or that `schema_violations` returns a sorted list and never raises. Task 1's own enumeration of new docstrings (*"the four layer `__init__.py` docstrings, and the opening docstrings of `model/flow_graph.py` and `adapters/json_file.py"*) leaves `adapters/schema.py` out. Add one opening sentence naming what the module owns, ahead of the ECMA-262 paragraph.
2. **`task_3_plan.md` / `task_2_plan.md` — the README's "standard library only" column is wider than the contracts enforce.** This is carried from round 0 and still open. Task 3 has the `model` row say it may import "the standard library only", and the `engine` row say `model` and the standard library. Its verification then asks that the `May import` column match `[tool.importlinter]` *"cell for cell"*. Task 2's contracts forbid only `jsonschema` in those two layers, plus the layer direction. A later runtime dependency imported into `model` or `engine` would pass both contracts while breaking the README's rule. So the "cell for cell" check cannot be met as written. Either have the README say that `jsonschema` is the confinement the contract enforces and that "standard library only" is a rule a reviewer checks by reading, or relax Task 3's verification to what the contracts can express.

That is not a static import, so neither Task 1's root-import grep nor `import-linter` sees it, and it is harmless. Still, the README rule Task 3 writes (*"No module inside the package imports from the package root"*) reads as absolute. Adding one clause that allows package-data resolution would keep a later reviewer from flagging it, or from copying the pattern for a real import.
