# Story: GraphScene static checker

## Context

This branch gives GraphScene its static checker: a pure library call that takes a graph and returns `Violation` values. It ports the five generic checks of `scripts/check-flow-graph.sh` → `THE CONTRACT` — 1 `reachable-from-start`, 2 `reaches-terminal`, 3 `fail-cycle-capped`, 8 `gate-in-round` and 9 `round-fan-out` — and restates them on the primitives a format-4 graph declares, never on harness names. It also adds the check the builder left as plain `str` ids "for a later static checker": every node, counter, path, report-slot and prompt name a graph uses must exist. Checks 4 to 7 read plugin documents, and the checks on what runs a node read agent definitions. Both stay harness-side, so `scripts/check-flow-graph.sh`, its fixtures under `schemas/flow-graph-check/` and its gate legs `3e` / `3f` are not touched. Everything lands in `graphscene/`, in five `graphscene` tasks in bottom-up order (engine checks, then the loading pipeline, then the public surface and loader tests, then the package README). The last task is the catch-all one (`general`): it wires the new fixtures into the root `validate:graphscene-schema` script and updates the root documents of record.

**What the checker reads: the typed `FlowGraph`, decided on the checker's own evidence.** Each criterion from the task prompt, weighed for the checker alone:
- **How the checks read.** Every ported check walks one edge set: a route edge's `to`, an interrupt edge's `resume`, a skip entry's `to` and a round's fan-out to its gates. Checks 2, 3 and 9 also look up what a binding's primitive is and what verdict an outcome declares. On the model those are `isinstance(edge, RouteEdge)`, `isinstance(graph.vocabulary.bindings.get(edge.binding), StopBinding)` and `graph.vocabulary.outcomes[name].verdict == "fail"`. On the mapping, every check would re-derive the edge class from whether `"binding"` is in the edge, and read the primitive back as a string. That is a second copy of the decision the builder already makes (`graphscene/src/graphscene/adapters/builder.py` → *"Which classes"*), and the same copy `vocabulary.py` carries today in `_Binding` / `_bindings`. Drafted both ways, `reaches-terminal`'s sink test reads `isinstance(edge, BindingEdge) and isinstance(bindings.get(edge.binding), StopBinding) or isinstance(edge, RouteEdge) and edge.on_cap is not None and isinstance(bindings.get(edge.on_cap.binding), StopBinding)` on the model. On the mapping it needs `_mapping(edge)`, `"binding" in fields`, `_mapping(fields.get("onCap"))` and a string compare against `"stop"` behind a `_bindings` table.
- **Where it runs and who holds what there.** The checker runs after the build: inside `load_graph`, where the model is at hand, and as a public call the walker (#416) and a host holding a `FlowGraph` can make. The mapping would be forced only if the checker had to run before the build. It does not: the builder keeps every reference a `str`, so it builds a graph whose ids do not resolve without failing.
- **Violation paths.** This is the real cost of the model. Paths must be rebuilt in the serialized spelling. The checks name only three camelCase keys — `onCap`, `roundCounts` and `revisionNote` — and each check writes them literally in its f-string path, as `vocabulary.py` already writes `onCap`. Every clause's planted test asserts the exact path, so a snake_case slip fails a test. The cost is accepted.
- **Type checking.** Under strict `mypy` the model gives typed fields. The mapping gives `object` values coerced back through `_mapping` and `_strings`, which hide a wrong shape as `{}` / `[]` instead of failing.

**What follows for the vocabulary check.** The checker reads the model, so the vocabulary check moves onto it in this branch (Task 3), and every engine check reads one input. Loading becomes **schema → build → vocabulary → static**. `vocabulary_violations` takes a `FlowGraph`, its planted test graphs go through the builder, its `_mapping` / `_strings` / `_Binding` / `_bindings` helpers go, and `build_flow_graph`'s docstring stops promising a vocabulary-valid input. Its violations stay byte-identical and in document order, because the model keeps the file's key order.

**The other decisions this plan makes** (each one stated once here; the tasks restate the contract they implement):
- **Where it runs: both.** There is one public call, `graphscene.static_violations(graph: FlowGraph) -> list[Violation]`, defined in `graphscene/src/graphscene/engine/static_check.py`. `load_graph` runs it as a new last stage, `Stage` member `"static"`, raised as `GraphError("static", found)`. Inside the call, the reference checks (`graphscene/src/graphscene/engine/references.py` → `reference_violations`, not public) run first. When they find anything, their violations are returned alone and the graph checks never run, because a walk over a graph naming a missing node would only add noise. This is the same rule the vocabulary check applies to an undeclared binding.
- **Check ids: carried in the reason, not in a new field.** `Violation` stays `(path, reason)`, the one error shape of every stage. Every static violation's reason opens with its check id, `<check-id>: <detail>`, the way the bash checker prints `<check-id>: <detail>`. The cutover can then compare ids without a model change. The reference check ids are `node-known`, `counter-known`, `path-known`, `report-slot-known`, `prompt-known` and `start-in-entries`. The graph check ids are the bash ones verbatim. Each id is one token with no space.
- **Harness names restated as primitives.** Check 2's `<escalate>` becomes any binding whose primitive is `stop`. Check 3's `FAIL` edge becomes an outcome declaring `verdict: fail`, and its `<ask>` exemption becomes "binding edges are not walked". Check 9's writer `returned` edge becomes "the writer routes at least one route edge to the round, and any of its route edges may". Check 8 drops `findingsFolder`, which #417 may move: a dispatch node that routes a fail verdict with no increment is a gate. The schema itself says a verdict is what a round's join reads off a gate (`graphscene/src/graphscene/schemas/flow-graph.schema.json` → `outcomeDeclaration.verdict`). On the harness's own format-4 graph (`cli/templates/scripts/flows/task_plan_writing.v4.graph.json`), that selector picks exactly the three reviewers of `plan_round`. Running both checkers on that graph is the cutover's job, not this branch's.
- **Fixtures.** There is one format-4 fixture per ported check, plus one for the reference stage, under `graphscene/tests/fixtures/flow_graph/`, named `static_negative_<check_id>.json`. Each is a copy of `valid_generic.json` with one change, and each fails with its own check id and no other. No test reads outside `graphscene/`.

**Top risks:** The first risk is that a fixture fails for the wrong reason, either by firing a second check or by failing the schema or vocabulary first. Task 2's suite asserts each fixture returns exactly its one violation, and Task 4 runs every fixture through `load_graph` and asserts stage `"static"` with that one path. The second risk is that moving the vocabulary check silently changes what it reports. Task 3 keeps every existing expected `Violation` in `graphscene/tests/engine/test_vocabulary.py` unchanged and only changes how the planted graphs are made. The third risk is a public name that exists but is not wired: Task 4 adds `static_violations` to both `__all__` lists and to `graphscene/tests/test_public_surface.py`, and its loader cases exercise the whole schema → build → vocabulary → static path.
