# Story: Retire the format-3 flow-graph bridge and ship the format-4 graph under the shipped name

## Context

This branch retires the format-3 bridge #413 added, now that #419 has moved the walker to Python and the walker reads format 4. It does three things. **First**, the format-4 planning graph becomes the one shipped file under the shipped name. `cli/templates/scripts/flows/task_plan_writing.v4.graph.json` is moved onto `cli/templates/scripts/flows/task_plan_writing.graph.json`, replacing the format-3 file there. `devscene-flow-walker` then finds its graph as `<flows>/<flow>.graph.json`. **Second**, the four checks of `scripts/check-flow-graph.sh` that read plugin documents are ported to `devscene-flow-host`, reading the format-4 graph: 4 `run-mode-id-known`, 5 `ledger-id-known`, 6 `findings-folder-in-core` and 7 `cap-matches-core`. Checks 1–3, 8 and 9 already run on that graph as `graphscene.static_violations`, inside every `load_graph`. **Third**, every remaining piece of the bridge is deleted: the format-3 schema and both of its fixture families, the generator and its drift check, the bash checker, the `validate:flow-graph*` npm scripts, gate legs `3c`–`3f` and `3i`, and every document that describes them. Gate legs `3g` and `3h` stay, for the format-4 schema. The remaining legs keep their ids; nothing is renumbered.

**Why a rename and not a re-point.** Every reader of the format-3 file reads it by the shipped name: the planning driver's two libraries (`cli/templates/scripts/lib/planning-node-lib.sh` → `PNL_GRAPH`, `PNL_REAP_JQ`; `cli/templates/scripts/lib/planning-driver-lib.sh` → `PD_ROUND_GATES`), the comment mirror above `hr_remote_planning_paths` in `cli/templates/scripts/lib/harness-run-lib.sh`, `cli/test/agent-return-schemas.test.mjs` → `GRAPH`, `cli/test/planning-node-lib.test.mjs` and `cli/test/watcher-planning-driver.test.mjs`. Once the format-4 graph sits under that name, each of them reads format 4 without an edit. That works because each reads only keys both formats share: dispatch nodes' `kind`, `agent` and `outcomes` keys, and round nodes' `gates`. The task prompt records that check, made on 2026-11-25. The only renames are therefore the ones that spell `.v4.graph.json`: `outerLoopScripts.ts`, the `flow-walker.sh` header, `cli/test/helpers/walker.mjs` → `WALKER_GRAPH_PATH`, `devscene_flow_host.commands.flow_walker.GRAPH_SUFFIX`, the flow host's suites, its README, and the three plugin files that name the graph.

**Where checks 4–7 live, decided here.** The task prompt left this open. They become a **test-support checker in `devscene-flow-host/tests/`**, `core_agreement.py`, run by its own suite `test_core_agreement.py` and so by gate 13's leg `13j`. They do not become a new verb or a module of the shipped package. The reason is that they are a dev-time gate over this repository, reading `plugin/instructions/…` by repo-relative path. An adopter's `<scriptsDir>/python/` copy of the package has no `plugin/` beside it. `check-flow-graph.sh` kept its flow-to-core table out of the shipped graph for the same reason: so that a file shipped to adopters never names a `plugin/` path. A support module under `tests/` keeps that property. Reading another layer's tracked file there is allowed test input, not an import (`.claude/context/devscene-flow-host.md` → `## What it may depend on`; `.claude/context/conventions.md` → `## The testing bar`). Each finding is a `graphscene.Violation` whose reason opens with its check id, `<check-id>: <detail>`, the same shape `static_violations` uses. **No suite compares the bash and Python checkers.** The bash checker is deleted on this branch, so there is no second checker to compare, and the `check_document` export question in the prompt's leads does not arise.

**What the branch leaves to a person, after merge.** The prompt's Decided section (2026-11-25) rules out any pruning, migration step or `doctor` check. `init` removes nothing it stops shipping. An adopter's stale `<scriptsDir>/flows/task_plan_writing.v4.graph.json` stays, and no adopter-facing text names it. That follows `harness-runs/lessons.md` → *"A rename declared breaking ships no compatibility path"*. This repository's own self-adopted copies under `scripts/` (`scripts/flows/`, `scripts/flow-walker.sh`, `scripts/lib/`) are **not** edited by any task. They are `init`'s output, re-rendered after merge. The re-render writes the format-4 graph over `scripts/flows/task_plan_writing.graph.json`. After that, the main checkout's walker must be re-provisioned before the stale `scripts/flows/task_plan_writing.v4.graph.json` is deleted by hand: the walker installs the flow host as a wheel (#478), and the old wheel looks for the `.v4` name. During this branch's own run, the walker is the main checkout's and reads the main checkout's graph, so nothing on the branch reaches it before merge.

**The order, and one red window that is expected.** The tasks follow the configured layer order: `cli`, `plugin`, `graphscene`, `devscene-flow-host`, then `general` last. The rename crosses the `cli` / `devscene-flow-host` boundary, so it is two tasks. **From Task 1 until Task 5 lands, the flow host's suites and the `cli/test/flow-walker*` suites fail.** Task 1 moves the file, and Task 5 moves `GRAPH_SUFFIX` and the suites' `_GRAPH` paths. No task in between edits or runs those suites, and every gate runs after the last task. The same holds for gate legs `3c`, `3e`, `3f`, `3g` and `3i` from Task 1 until Task 7. Task 7 deletes `3c`, `3e`, `3f` and `3i`, and re-points `validate:graphscene-schema` (leg `3g`) at the renamed file.

Top risks: The rename strands a reader that still spells `.v4.graph.json`. Task 1 and Task 5 guard this: each ends on a `git grep` for that spelling over its own layer, and Task 3 does the same over `plugin/`. The ported checks 4–7 could pass vacuously, which is the property the bash checker guarded with *"refusing to pass without them"*. Task 6 keeps that clause for every owner document, and asserts each clause on planted input as well as on the real tree. Finally, retiring the gate legs could leave a document describing gates that no longer run. Task 7 removes the legs, and Tasks 8 and 9 own every document the scope register below reaches.

Manual setup required:
- After merge, from this repository's main checkout: run a forced self-adopt render of the merged default branch, as #481 did for #419. It rewrites `scripts/flows/task_plan_writing.graph.json` (now format 4), `scripts/flow-walker.sh` and the libraries under `scripts/lib/`. This is a post-merge step the task prompt rules out of the run, and it depends on Tasks 1 and 5.
- After the re-render: run `bash scripts/flow-host-provision.sh` outside the sandbox, so the main checkout's walker installs the flow host carrying Task 5's `GRAPH_SUFFIX`.
- After the re-provision, and only then: delete `scripts/flows/task_plan_writing.v4.graph.json` by hand. The re-render no longer writes it, and the walker no longer reads it. Deleting it before the re-provision leaves the old wheel with no graph. This depends on Tasks 1 and 5.
