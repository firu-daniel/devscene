   The finding's Problem §1 argues the top-level refusal is unfounded: *"Staging `.` commits the tip plus every path as the working tree holds it, which is exactly that same set. The only difference is that the deletion is no longer lost."* Fix step 2 likewise says the climb "stages nothing extra". That holds for the set of *changed* paths, but not for what `commit-on-branch.sh` does with a directory entry. In `cli/templates/scripts/commit-on-branch.sh` → the STAGING POLICY loop (`if [ -d "$top/$p" ] && [ ! -L "$top/$p" ]; then` … `[ -n "$rel" ] || rel=.`), a directory is expanded into **every** path the tip holds under it (`main_git ls-tree -r -z "$old_tip" -- "$rel"`) plus every index and untracked path there. All of those go into `commit_paths`. Then the `NO FILTER DRIVER RUNS` block (`wt_git check-attr -z --stdin filter`) fails the whole commit with `'$a_path' selects a filter driver, which this wrapper never runs` if **any** of them carries a `filter` attribute, even an unchanged one.
   So with `p=.`, any adopter repository that has a single filter-attributed tracked file anywhere (git-lfs is the common case) still refuses every unit that deletes or renames a root file. The finding says its fix removes that halt, and it does not. The climb in step 2 also widens a nested whole-directory deletion to an ancestor, which can now pull a filtered file into a commit that touched none. It also turns each such commit into a whole-tree `ls-tree -r` and hash, where it used to be a single-directory one. The fix loop would implement this fix as written, rewrite the library header to state the false "stages nothing beyond the listing" rationale, and add tests that pass only because the fixture has no filter attribute.

The second keeps the ancestor approach but states and handles the filter-attribute and whole-tree consequences explicitly. Either way, add a step-4 test case where the fixture carries a `.gitattributes` `filter=` entry on an unrelated tracked file. Assert that the top-level deletion and the whole-directory deletion still commit.
