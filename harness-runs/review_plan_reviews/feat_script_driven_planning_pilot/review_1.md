With `tools: []`, every node agent that has a non-empty `tools:` line is reaped as `error`. So `pd_undelivered` never runs, `PD_STRIKES` never reaches 3, nothing self-pauses, and the case's assertions (`status` `'paused'`, one `paused` notification naming the overload) fail. The fix loop would then be stuck on a test the finding itself specified.

For example, place the check after the existing `const tools = toolsLine.slice('tools:'.length)…` line in the node branch (or compute `tools` the same way before the early exit), and write `{ type: 'system', subtype: 'init', session_id: 'stub', tools }` alone. Then correct the sentence that calls `tools: []` the same shape `planning-driver-control.test.mjs` uses.
